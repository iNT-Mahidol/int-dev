# Design Profile: INT System Standard

Design intent: system
Component library: shadcn/ui
Fonts: Kanit (Google Fonts), Geist Mono for code
Themes: light, dark
Source: INT System Standard (Claude Design System artifact), copied 2026-11-06.
Applies to: INT internal systems. Client projects use their own DESIGN.md.

มาตรฐานกลางการพัฒนาระบบของ INT: ทุกระบบที่ INT สร้าง ทั้งระบบงานภายในและระบบที่บุคคลภายนอกใช้ ใช้ token, ตัวอักษร, โครงหน้า, component, รูปแบบหน้าจอ และวิธีเขียนข้อความชุดเดียวกัน คนที่เคยใช้ระบบหนึ่งของ INT ต้องใช้ระบบถัดไปได้ทันทีโดยไม่ต้องเรียนใหม่ มาตรฐานนี้ไม่ผูกกับระบบใด: ทีมพัฒนาหรือ Claude Code ของแต่ละระบบอ่านแล้วปรับระบบของตัวเองเข้ามาตรฐานได้ทันที ตามขั้นตอนในส่วน "นำมาตรฐานไปใช้กับระบบ" ส่วนที่ติดป้าย **ข้อเสนอ** คือกฎที่ยังรอการยืนยัน สี โลโก้ และน้ำเสียงอ้างอิงคู่มือแบรนด์ INT (ปรับปรุง 18 เม.ย. 2569) ซึ่งแปลเป็นกฎของหน้าจอไว้ในส่วน "แบรนด์ในระบบ" ส่วนวิธีทำงานตั้งแต่ตีโจทย์จนส่งงานอยู่ในส่วน "กระบวนการพัฒนา"

## ขั้นต่ำที่ทุกระบบต้องมี

1. **Token จากแหล่งเดียว**: ใช้ `tokens.css` ของมาตรฐานนี้ (CSS variables เช่น `--primary`, `--background`) ตรง ๆ ห้าม copy ค่า hex ไปเขียนเอง; ใน Tailwind ผูกเป็น class เชิงความหมาย (`bg-primary`); ระบบที่ไม่ใช้ Tailwind อ้าง `var(--primary)` ตรง ๆ
2. **ฟอนต์**: Kanit สำหรับทุกข้อความ, Geist Mono สำหรับรหัส
3. **component จาก shadcn/ui ของมาตรฐานนี้** และโครงหน้า `AppShell`: แถบน้ำเงินที่มีโลโก้ INT + ชื่อระบบ และเมนูตามสิทธิ์, main กว้างไม่เกิน `content-max`
4. **ชื่อระบบ**: "INT" ตามด้วยชื่อภาษาอังกฤษสั้น ๆ หนึ่งถึงสองคำ เขียน "INT" ตัวใหญ่ทั้งหมดเสมอ (ข้อเสนอ)
5. **ภาษาไทยก่อน และวันที่แบบ พ.ศ.**
6. **ผ่านรายการตรวจก่อนส่งงาน** ในส่วน "กระบวนการพัฒนา"

## shadcn/ui คือมาตรฐาน component

ทุกระบบของ INT สร้างหน้าจอด้วย **shadcn/ui** (ชุด component ที่ copy โค้ดมาไว้ในโปรเจกต์ของเราเอง สร้างบน Radix UI ซึ่งจัดการคีย์บอร์ดและ screen reader ให้ แต่งด้วย Tailwind CSS v4) ร่วมกับ lucide-react (ไอคอน), sonner (toast) และ class-variance-authority (variant ของปุ่มและป้าย) component ทุกตัวในหน้านี้เป็น React ที่ทำงานจริง ทั้งในพรีวิวและใน `components/bundle.js`

**เริ่มระบบใหม่ (React / Next.js)**
1. `npx shadcn@latest init` แล้วแทนที่ `globals.css` ด้วย `components/src/styles/globals.css` ของมาตรฐานนี้ ไฟล์นี้ map สีทุกตัวของ Tailwind ไปที่ token (`bg-primary` → `var(--primary)`), อ่านมุมโค้งและฟอนต์จาก token, ให้ `dark:` อ่านจาก `data-theme` และ**ปิดสีชุดเริ่มต้นของ Tailwind ทั้งหมด** คลาสอย่าง `bg-blue-500` จึง build ไม่ผ่าน
2. โหลด `tokens.css` ก่อน `globals.css` และใส่ `themeInitScript` ใน `<head>`
3. copy `components/src/ui/*` ไปไว้ที่ `components/ui/` และ `components/src/int/*` ไปไว้ที่ `components/int/` ในโปรเจกต์ (นี่คือ shadcn ที่ปรับให้เป็นแบบ INT แล้ว) แล้วติดตั้ง Radix, lucide-react, sonner, class-variance-authority, clsx และ tailwind-merge
4. component ที่มาตรฐานยังไม่มี ให้เพิ่มด้วย `npx shadcn@latest add <ชื่อ>` แล้วปรับให้ตรงกฎในหน้านี้ ได้แก่ ใช้แต่ token, focus ring เส้นทึบ, ไม่มี `dark:` และข้อความไทย จากนั้นส่งกลับเข้ามาตรฐานนี้
5. ระบบที่ยังใช้ React 18 ต้องห่อ component ด้วย `React.forwardRef` เหมือนใน `components/src` (React 19 ไม่ต้อง) ถ้าไม่ห่อ เมนูและ tooltip ของ Radix จะหาตำแหน่งไม่เจอ

**ระบบที่ไม่ใช่ React** (ข้อเสนอ): ถ้าแพลตฟอร์มมี React อยู่แล้ว (เช่น WordPress มี script handle `react` และ `react-dom`) ให้โหลด `bundle.js` กับ `bundle.css` ของมาตรฐานนี้ แล้ว mount component จาก `window.IntSystems` เป็นจุด ๆ ในหน้าได้ ส่วนหน้าที่เป็น HTML จาก PHP ล้วน ต้องใช้ token กับ class ชุดเดียวกัน และต้องมีพฤติกรรมเดียวกับตารางด้านล่าง

**ห้าม**: เขียน component พื้นฐานใหม่เองในเมื่อ shadcn มีอยู่แล้ว, ใช้ UI library อื่น (MUI, Ant Design, Bootstrap), แก้ไฟล์ใน `components/ui` จนต่างจากมาตรฐานโดยไม่ส่งกลับมาที่นี่

## พฤติกรรมที่ต้องเหมือนกันทุกระบบ

helper ทั้งหมดมีอยู่ใน `components/src/lib` และใน `window.IntSystems` แล้ว ระบบที่ใช้ stack อื่นต้องทำให้ได้พฤติกรรมเดียวกัน:

| helper | พฤติกรรมที่ทุกระบบต้องมี |
| --- | --- |
| `roleCan` (อยู่ในแต่ละระบบ) | ซ่อนปุ่มและเมนูที่ผู้ใช้ไม่มีสิทธิ์ และ server ตรวจสิทธิ์ซ้ำทุกครั้ง |
| `runAction` → `toast.promise` | ทุกการกระทำแสดง "กำลัง…" แล้ว "…แล้ว" หรือ error ที่บอกวิธีแก้ ใน toast จุดเดียวของหน้าจอ |
| `formatThaiDate`, `formatThaiDateTime` | วันที่ "29 ต.ค. 2569" ไม่แสดงแบบ ISO |
| `maskEmail`, `maskPhone` | ข้อมูลส่วนบุคคลปกปิดเป็นค่าเริ่มต้น |
| `STATUS` + `StatusBadge`, `ROLE_LABELS` | ชื่อ role และสถานะเก็บที่เดียว ใช้คำเดียวกันทั้งระบบ |
| `ThemeToggle`, `themeInitScript` | สามตัวเลือกธีม จำค่าไว้ และไม่กระพริบตอนโหลด |
| `version` + `ConflictError` | แก้พร้อมกันไม่เขียนทับเงียบ ๆ แต่แจ้งให้โหลดใหม่ |

## หลักการ

1. **ข้อมูลก่อน แบรนด์ทีหลัง.** ผู้ใช้ระบบของ INT ส่วนใหญ่คือบุคลากรที่ทำงานเดิมซ้ำทุกวัน (เจ้าหน้าที่, ผู้ดูแลระบบ, ผู้ตรวจสอบ) หน้าจอต้องสแกนง่ายและคาดเดาได้ สีแบรนด์มีไว้บอกสิ่งที่กดได้และตัวตนของระบบ ไม่ใช่ตกแต่ง
2. **หนึ่งรูปแบบต่อหนึ่งงาน ในทุกระบบ.** รายการใช้ `ListPage` รายละเอียดใช้ `DetailPage` ฟอร์มสั้นใช้ `FormDialog` สถานะใช้ `StatusBadge` ผลการกระทำใช้ toast เสมอ ห้ามคิดรูปแบบใหม่ถ้ารูปแบบเดิมใช้ได้
3. **ซ่อนสิ่งที่ทำไม่ได้.** ปุ่มและเมนูที่ผู้ใช้ไม่มีสิทธิ์ไม่แสดง แต่ server ตรวจสิทธิ์ซ้ำทุกครั้ง
4. **ไม่มีอะไรหายเงียบ ๆ.** ลบไม่ได้ให้ปิดใช้ แก้พร้อมกันให้แจ้ง conflict ทุกการเปลี่ยนมีประวัติ
5. **ภาษาไทยก่อน.** ข้อความทั้งหมดเป็นภาษาไทย วันที่เป็น พ.ศ. ชื่อเฉพาะภาษาอังกฤษคงไว้ตามจริง

## ลำดับความสำคัญทางสายตา (Visual Hierarchy)

ทุกหน้าจอต้องบอกได้ทันทีว่า "หน้านี้คืออะไร ทำอะไรได้ และข้อมูลอยู่ตรงไหน" ตามลำดับนั้น จึงแบ่งทุกอย่างบนหน้าเป็น 3 ระดับ แต่ละระดับมีโควตาและเครื่องมือของตัวเอง (ดูตัวอย่างที่ทำงานจริงได้ในหน้า `VisualHierarchy`)

| ระดับ | อะไรอยู่ในระดับนี้ | ทำให้เด่นด้วย | โควตาต่อหน้าจอ |
| --- | --- | --- | --- |
| **1 จุดเด่น** | `page-title` (h1), ปุ่ม `primary`, ส้มหนึ่งจุด (ถ้ามี) | `page-title` 30px/600, พื้นทึบ `primary` | h1 หนึ่งตัว, primary หนึ่งปุ่ม, ส้มหนึ่งจุด |
| **2 โครงสร้าง** | `section-title`, ตัวเลขสำคัญ (`Metric`), ชื่อในคอลัมน์แรกของตาราง, `StatusBadge` | น้ำหนัก 500–600, ระยะคั่นกลุ่ม | ไม่จำกัด แต่ต้องเล็กกว่าระดับ 1 อย่างชัดเจน |
| **3 ข้อมูลรอง** | คำอธิบายหน้า, ข้อความช่วย, meta, วันที่, หัวคอลัมน์ | `muted-foreground`, ขนาด 12–14px | ไม่จำกัด |

แถบน้ำเงินของ `AppShell` ไม่นับเป็นระดับใด เพราะเป็นโครงของทุกหน้า แต่เพราะมันหนักที่สุดบนจอ เนื้อหาใต้แถบจึงต้องเว้น `space-10` ก่อนถึง h1 และห้ามวางปุ่มหลักหรือพื้นสีเข้มชิดใต้แถบ

**เครื่องมือ 5 อย่าง ใช้ตามลำดับนี้ (อย่างแรกก่อนเสมอ)**

1. **ขนาด**: ระดับที่ติดกันต่างกันอย่างน้อย 1.25 เท่า (`page-title` 30 → `metric` 24 → `section-title` 20 → `body` 16 → `ui`/`small` 14 → `caption` 12) ในหน้าทำงานห้ามใช้อะไรที่ใหญ่กว่า `page-title`
2. **ระยะห่าง (proximity)**: ระยะในกลุ่มต้องน้อยกว่าระยะระหว่างกลุ่มเสมอ ตามบันได `space-2` (หัวกับคำอธิบาย) → `space-4` (ช่องในฟอร์ม) → `space-6` (ระหว่างส่วน) → `space-10` (ขอบบนล่างของ main) ห้ามใช้ระยะเท่ากันทั้งหน้า
3. **ความทึบของสี**: แยกระดับด้วย `foreground` กับ `muted-foreground` ก่อน แล้วจึงใช้น้ำเงิน (`primary`) และใช้ส้มเป็นทางเลือกสุดท้าย
4. **ความลึก**: มีแค่สองระดับ คือ `shadow-raised` สำหรับสิ่งที่ลอยแต่ไม่บังหน้า (เมนู รายการ select toast tooltip) และ `shadow-overlay` สำหรับสิ่งที่บังหน้า (dialog) ส่วนการ์ด ตาราง และแผงในหน้าใช้ `border` ไม่ใช้เงา
5. **ตำแหน่ง**: หน้าทำงานอ่านตามรูปตัว F คือหัวข้อชิดซ้าย ปุ่มชิดขวา และคอลัมน์แรกของตารางสำคัญที่สุด ส่วนหน้า login และหน้าสาธารณะอ่านตามรูปตัว Z คือโลโก้ → หัวข้อ → ปุ่ม

**ตรวจด้วย squint test**: ถ่ายภาพหน้าจอแล้วเบลอประมาณ 4px ต้องยังเห็นสามอย่างตามลำดับ คือ หัวข้อหน้า → ปุ่มหลัก → กลุ่มเนื้อหา ถ้าสิ่งที่เด่นที่สุดไม่ใช่สามอย่างนี้ (ยกเว้นส้มหนึ่งจุดที่ตั้งใจให้รีบดู) แปลว่าลำดับผิด

## สี: 60 / 30 / 10

- **60% ขาว**: `background`, `card`, `popover` เป็นพื้นของทุกหน้า ข้อความใช้ `foreground` ข้อความรองใช้ `muted-foreground`
- **30% น้ำเงิน**: ส่วนใหญ่มาจาก**แถบน้ำเงิน** คือ header กับเมนูหลักที่รวมเป็นก้อนเดียว สูงราว 108px บนพื้น `brand` (Deep Blue) ใช้สีเดียวกันทั้งสองธีม; อีกส่วนคือ `primary` สำหรับปุ่มหลักและลิงก์ และ `brand` บนแผงแบรนด์ของหน้า login ข้อความบนพื้น `brand` ใช้ `brand-foreground` (ขาว 13.1:1) และ `brand-muted-foreground` (6.9:1)
- พื้นที่เนื้อหาใต้แถบน้ำเงินยังเป็นพื้นขาวเสมอ ห้ามทำการ์ด ตาราง หรือแถบหัวหน้าเป็นน้ำเงินเพิ่มเพื่อให้ได้สัดส่วน 30%
- **10% ส้ม**: `highlight` มีได้**หนึ่งจุดต่อหน้าจอ** เช่น จุดท้ายเส้นชีพจรบนหน้า login แถบ "กำลังใช้งานแทน" หรือป้าย "ใกล้ครบกำหนด" **ห้ามใช้ส้มเป็นปุ่ม**
- **ส้มไม่เป็นข้อความบนพื้นขาว** (contrast 2.6:1) และ **Light Blue ไม่เป็นข้อความเนื้อหาหรือลิงก์บนพื้นขาว** (3.1:1) แม้คู่มือแบรนด์จะใช้แบบนั้นในงานพิมพ์ เหตุผลและที่ที่ใช้ได้อยู่ในส่วน "แบรนด์ในระบบ"
- `destructive` สำหรับ error และการกระทำที่ย้อนยากเท่านั้น
- `secondary` และ `accent` (ฟ้าอ่อน) สำหรับพื้นของ badge สถานะปกติ เมนูที่เลือก และปุ่มรอง
- `border` สำหรับเส้นแบ่งทุกเส้น `input` สำหรับขอบช่องกรอก `ring` สำหรับ focus ring
- ใน component ใช้ token เชิงความหมายเท่านั้น (`bg-primary`, `text-muted-foreground`) **ห้ามอ้าง `int-*`** (นั่นคือ palette ดิบ) ห้าม class สีของ Tailwind (`bg-blue-500`, `text-white`) และห้ามสี hex; ต้องการสีใหม่ให้เพิ่ม token ที่มาตรฐานนี้ก่อน แล้วเพิ่มคู่ข้อความ/พื้นใน test ตรวจ contrast ของระบบ (ตรวจตาม WCAG AA)
- ทุกธีมต้องผ่าน: ข้อความ 4.5:1 บนพื้นของมัน ขอบ control และ focus ring 3:1

## ธีมสว่างและมืด

ทุกระบบรองรับสองธีม `light` และ `dark` ผู้ใช้ใหม่เริ่มที่ "ตามระบบ" (`prefers-color-scheme`) และเปลี่ยนเองได้จาก `ThemeToggle` ใน header ธีมเปลี่ยน**ค่าสีเท่านั้น** ไม่เปลี่ยน layout ระยะ หรือฟอนต์ และไม่มีระบบไหนเลือกมีธีมเดียว

| Token | สว่าง | มืด | เหตุผล |
| --- | --- | --- | --- |
| `background` | ขาว | `int-navy-950` | พื้น 60% ของจอ |
| `card`, `popover` | ขาว | `int-navy-900` | แยกจากพื้นด้วย `border` ไม่ใช้เงา |
| `foreground` / `muted-foreground` | `int-ink` / `int-slate` | `int-snow` / `int-mist` | |
| `primary` | Deep Blue | Light Blue | Deep Blue บนพื้นมืดมองไม่เห็น ธีมมืดจึงใช้ Light Blue |
| `primary-foreground` | ขาว | `int-navy-950` | ขาวบน Light Blue ได้แค่ 3.1:1 |
| `secondary`, `accent` | `int-blue-100` | `int-navy-700` | |
| `destructive` | `int-red` | `int-red-light` | |
| `input` | Metallic Silver | Metallic Silver | ขอบช่องกรอกผ่าน 3:1 ทั้งสองธีม |
| `overlay` | navy-950 โปร่ง 50% | ดำโปร่ง 60% | ฉากหลัง dialog |
| `brand`, `highlight`, `ring` | เหมือนกันทั้งสองธีม | | แถบน้ำเงิน แผงแบรนด์ และส้มเป็นตัวตนของ INT ไม่เปลี่ยนตามธีม; ในธีมมืดแถบน้ำเงินแยกจากพื้นด้วยเส้น `border` |

- คู่สีที่ตรวจแล้วผ่าน WCAG AA ทั้งสองธีม: ข้อความทุกคู่ 4.5:1 ขึ้นไป (`primary` บน `card` ธีมมืดได้ 5.3:1, `muted-foreground` บน `card` 6.9:1), `ring` และ `input` 3:1 ขึ้นไป
- บนพื้นที่ธีมมืดทำให้สว่างขึ้น (`primary`, `highlight`) ใช้ `*-foreground` ของมันเสมอ ไม่ใช้ขาวตายตัว
- โลโก้: แบบ Reverse บนแถบน้ำเงินและแผงแบรนด์เสมอ; แบบ Primary ใช้บนพื้นขาวของธีมสว่าง (เช่น เอกสารหรือหน้าพิมพ์) ห้ามกลับสีด้วย `filter: invert()`
- เงามองไม่เห็นบนพื้นมืด จึงเป็นอีกเหตุผลที่แยกชั้นด้วย `border`
- กราฟใช้ `chart-1`–`chart-5` ซึ่งมีค่าแยกตามธีมแล้ว ภาพถ่ายไม่กลับสี

## ตัวอักษร

- ฟอนต์เดียวทุกระบบคือ **Kanit** (`sans`, น้ำหนัก 300–700) แทน FC Vision และ Hubot Sans ของคู่มือแบรนด์ โดยคงบทบาท Lead / Headline / Body ตามคู่มือ (ตารางเทียบอยู่ในส่วน "แบรนด์ในระบบ"); รหัสและ id ใช้ **Geist Mono** (`mono`)
- หนึ่งหน้ามี `page-title` (h1) หนึ่งตัวเท่านั้น หัวข้อส่วนและหัว dialog ใช้ `section-title`
- ข้อความอธิบายหน้าใช้ `body` สี `muted-foreground` กว้างไม่เกินราว 65 ตัวอักษร
- ปุ่ม ตาราง label และเมนูใช้ `ui`; ข้อความช่วยและข้อมูลรองใช้ `small`; badge ใช้ `caption`
- `display` และ `eyebrow` (บรรทัดนำเหนือหัวข้อ) ใช้บนแผงแบรนด์เท่านั้น
- ตัวเลขในตารางใช้ `tabular-nums`; ตัวเลขสำคัญหรือตัวเลขสรุปใช้ `metric` (24px/600) ผ่าน component `Metric`
- กลุ่ม **Marketing** (`hero` 48px, `section-heading` 30px, `lead` 20px) ใช้ได้เฉพาะหน้าสาธารณะ เช่น หน้า landing หรือหน้าแนะนำบริการ ห้ามใช้ในหน้าทำงานหลัง login หน้าหนึ่งมี `hero` ได้ตัวเดียวและทำหน้าที่เป็น h1

## ระยะและ layout

- คอลัมน์เนื้อหากว้างไม่เกิน `content-max` (1280px) ขอบข้าง `space-4` บนมือถือและ `space-6` ตั้งแต่ `sm`; header แถบใช้แทน เมนู และ main ใช้คอลัมน์เดียวกัน
- main เว้นบนล่าง `space-10`; ส่วนต่าง ๆ ในหน้าห่างกัน `space-6`; หัวกับคำอธิบายห่าง `space-2`; ช่องในฟอร์มห่าง `space-4`
- ใช้ flex/grid กับ `gap` ไม่ใช้ margin ทีละชิ้น; ทุก grid ยุบเหลือคอลัมน์เดียวที่ความกว้างมือถือ ตารางกว้างเลื่อนแนวนอนในกรอบของตัวเอง
- มุมโค้ง: ปุ่ม การ์ด dialog `radius-lg`; ช่องกรอก `radius-md`; badge และ avatar `radius-full`
- แยกชั้นด้วย `border` เป็นหลัก เงามีสองระดับเท่านั้น: `shadow-raised` (เมนู, select, toast, tooltip) และ `shadow-overlay` (dialog); ใน Tailwind เขียน `shadow-(--shadow-raised)` ห้ามใช้ `shadow-sm`/`md`/`lg` ของ Tailwind

## โครงสร้างของทุกระบบ

```
┌ แถบใช้แทน (highlight) — เฉพาะระบบที่ผู้ดูแลใช้งานแทนผู้ใช้ได้ ──┐
╔ แถบน้ำเงิน (brand, sticky) ═══════════════════════════════════╗
║ Header: โลโก้ Reverse + ชื่อระบบ ...... ธีม · avatar ชื่อ/role ║
║ เมนูหลัก: หน้าทำงานของระบบ … · ตั้งค่าระบบ                     ║
╚═════════════════════════════════════════════════════════════════╝
├ main (max 1280px)                                               ┤
│   ListPage   → หน้ารายการ        (/researchers)                │
│   DetailPage → หน้ารายละเอียด    (/researchers/[id])           │
│   FormDialog เปิดจากปุ่มบนสองหน้านี้                              │
└─────────────────────────────────────────────────────────────────┘
หน้า login: แผงแบรนด์ (brand, 1 ส่วน) | ฟอร์มบนพื้นขาว (2 ส่วน)
```

- **แถบน้ำเงิน**: header กับเมนูหลักอยู่บนพื้น `brand` ต่อกันเป็นก้อนเดียว คั่นด้วยเส้นขาวโปร่ง 12% และค้างอยู่ด้านบนเมื่อเลื่อนหน้า (sticky) โลโก้ใช้แบบ Reverse เสมอ ชื่อระบบเป็นสีขาว
- **เมนูหลัก**: แสดงเฉพาะเมนูที่ผู้ใช้มีสิทธิ์ เมนูที่ไม่ได้เลือกใช้ `brand-muted-foreground`; เมนูที่เลือกอยู่ใช้ตัวอักษรขาวกับเส้นใต้ 3px สี `brand-accent` (4.2:1); hover เป็นพื้นขาวโปร่ง 8% หน้าตั้งค่ารวมไว้ใต้ "ตั้งค่าระบบ" ซึ่งอยู่ท้ายสุด
- **ห้ามใช้ส้มในแถบน้ำเงิน** แม้ส้มบนน้ำเงินจะเข้ากัน เพราะส้มจุดเดียวของหน้าสงวนไว้ให้สิ่งที่ต้องรีบดู เช่น แถบ "กำลังใช้งานแทน"; และห้ามแบ่งแถบเป็นน้ำเงินสองเฉด เพราะเส้นใต้สี Light Blue บน INT Blue จะเหลือ contrast ไม่ถึง 3:1
- **URL**: หน้าทำงานอยู่ที่ระดับบน (`/researchers`) หน้าตั้งค่าอยู่ใต้ `/admin`; ตัวกรอง แท็บ หน้า อยู่ใน search params เสมอ เพื่อให้แชร์ลิงก์และกดย้อนกลับได้

## ข้อความ (UX writing)

- เรียกสิ่งต่าง ๆ ด้วยคำที่ผู้ใช้รู้จัก: "หน่วยงาน", "ปิดใช้", "บันทึกการใช้งาน" ไม่ใช่ "organization", "deactivate", "audit log" คำเดียวกันต้องใช้เหมือนกันทุกระบบของ INT
- ปุ่มเป็นกริยาที่บอกผล: "บันทึก", "เชิญ", "ปิดใช้", "เลิกใช้แทน" ไม่ใช้ "ตกลง" หรือ "ยืนยัน" ลอย ๆ
- Toast: "กำลังบันทึก…" → "บันทึกแล้ว"; error บอกว่าผิดอะไรและทำอย่างไรต่อ ("ข้อมูลนี้ถูกแก้โดยผู้ใช้อื่นแล้ว โหลดหน้าใหม่แล้วแก้อีกครั้ง") ไม่ขอโทษ ไม่คลุมเครือ
- คำอธิบายใต้หัวหน้าบอกกฎของข้อมูลในหนึ่งย่อหน้า เช่น "ลบไม่ได้ ปิดใช้ได้อย่างเดียว"
- วันที่ "29 ต.ค. 2569"; วันเวลา "29 ต.ค. 2569 14:30 น."; ไม่แสดงวันที่แบบ ISO ให้ผู้ใช้
- เขียนชื่อองค์กรว่า "INT" เสมอ
- หน้าทำงานใช้ "เสียงระบบ" ที่ตรงและสั้นตามหมวดนี้ ส่วนคำสร้างแรงบันดาลใจจากคลังคำศัพท์ของแบรนด์ใช้ได้แค่บนแผงแบรนด์และหน้า landing
- ไม่ใช้ emoji ในข้อความหรือหัวข้อ
- ข้อมูลส่วนบุคคลปกปิดเป็นค่าเริ่มต้น (`s***@mahidol.ac.th`); ประวัติและหน้าที่ผู้ใช้เห็นเรียกผู้ดูแลว่า "ผู้ดูแลระบบ" ไม่ระบุตัว

## ไอคอน

- ใช้ **lucide-react** ชุดเดียว (ระบบที่ไม่ใช่ React ใช้ชุด Lucide แบบ SVG) ขนาด 16px ในปุ่มและ 20px ในหัวข้อ สีตามข้อความรอบข้าง
- ไอคอนประกอบข้อความเสมอ ปุ่มที่มีแต่ไอคอนต้องมี `aria-label` ภาษาไทย
- พรีวิวในหน้านี้ใช้ไอคอน lucide จริงผ่าน `IntSystems.Icons` ส่วนในแอปให้ import จาก `lucide-react` ตรง ๆ

## สถานะและการตอบสนอง

- โหลด: skeleton ที่รูปทรงใกล้ของจริงทุกส่วนที่อ่านข้อมูล (React: `<Suspense fallback={<Skeleton />}>` หรือ `loading.tsx` ของ Next.js)
- ว่าง: บอกว่าที่นี่จะมีอะไรและวิธีเพิ่มรายการแรก
- การกระทำ: toast จุดเดียวของหน้าจอ (`runAction()` → `toast.promise`, `Toaster` mount ครั้งเดียวใน root layout)
- focus ring `ring` ทุก control ที่กดได้; เคารพ `prefers-reduced-motion`
- การเคลื่อนไหวมีจุดเดียว: เส้นชีพจรบนแผงแบรนด์วาดตัวเองตอนโหลด (reduced motion: วาดเสร็จทันที)

## ห้าม

- ปุ่มสีส้ม, สีส้มมากกว่าหนึ่งจุดต่อหน้า, ข้อความสีส้มหรือ Light Blue บนพื้นขาว
- h1 หรือปุ่ม `primary` มากกว่าหนึ่งต่อหน้าจอ, ตัวอักษรที่ใหญ่กว่า `page-title` ในหน้าทำงาน, เงาที่ไม่ใช่ `shadow-raised` หรือ `shadow-overlay`
- ริบบิ้น N, ภาพถ่าย หรือ motif ตกแต่งในหน้าทำงาน (ใช้ได้บนแผงแบรนด์และหน้า landing)
- สี hex หรือ class สี Tailwind ใน component
- การ์ดซ้อนการ์ด, เงาแทนเส้นแบ่ง, gradient นอกจาก `bg-brand-gradient` บนแผงแบรนด์
- โหลดข้อมูลฝั่ง client หลังหน้าแสดงแล้ว (`useEffect` fetch), toast ตอนโหลดหน้า
- แสดงปุ่มที่ผู้ใช้กดแล้วจะถูกปฏิเสธเพราะไม่มีสิทธิ์
- ระบบใหม่ที่ตั้งสี ฟอนต์ หรือรูปแบบหน้าจอของตัวเองโดยไม่ผ่านมาตรฐานนี้
